## How D differs from C

Set C (`docs/plans/2026-11-17-art-set-c.md`, branch `art/type-c`) stays as written; D is a separate attempt.

| | C (plan) | D |
|---|---|---|
| Character made by | PixelLab edit of a room crop (B's method) | `create_image_pixen` standalone with `no_background`, so no keyboard, chair or room fringe can be baked in |
| Depth order | fixed in advance: character behind the desk, desk front the only occluder | read from the reference crop and settled on the real room: chair is room art behind the body, forearm rests on the desk top, an occluder at the bottom ends the half-body (decision 2) |
| Poses | edits of the room crop | `edit_image_pixen` edits of the transparent rest sprite (a transparent input stays transparent) |
| Style match | by sharing the crop | palette sampled from the room and applied in Aseprite (`quantize_to_palette`), because the cheap generators take no style image |
| Budget | assumed about 5 a day, tools untested | from the price check below |

## PixelLab facts (checked 2026-11-17, free calls)

- Trial plan: 0 plan generations left; **5 a day**, banking up to 20.
- Usable: `create_image_pixen` (1; up to 512×512 area; `no_background` up to 65,536 px area), `edit_image_pixen` (1; input ≤ 256 px per side, output ≤ 65,536 px area), `remove_background` (1; ≤ 400×400 area).
- Too expensive for a day: `create_image_pro_flash` with the room as a style image (6). Kept as the fallback if the standalone character cannot be brought to the room's style in Aseprite (needs two days banked).
- Not on trial: `create_room`, `cut_out_room_furniture` (Tier 1), `inpaint_image`, character and object states (10+ each).
- Consequence: PixelLab still cannot return the room as layers. Layers come from (1) generating the character separately and (2) polygon cuts from the room, which cost nothing.

## Layering (mandatory, from `CLAUDE.md`)

Back to front, D uses the engine's groups unchanged:

| Group | D content |
|---|---|
| scenery | city (`VioletCityRain`, `VioletCityDusk`) and the rain sheet, seen through keyed-out glass |
| room | the empty room: walls, shelves, window frame, desk, **empty chair**, empty cat cushion, blank clock face, lamp |
| actors | character (standalone sprite, no furniture), then cat |
| foreground | pieces cut from the room that must cover a body: the bottom occluder that ends the half-body (decision 2) and, only if the room shows it crossing the body, the desk edge or chair arm |
| objects | clock digits, hotspots |

Rules carried into every task: a character or cat sprite contains **no furniture, keyboard, mug or background pixel**; anything that hides part of a body is a foreground piece cut from the room; anchors and hotspots sit inside the safe rectangle (452×328 at 14,12).

## Decisions

1. **Composition.** Side view of a desk at a wide window, boy in left-facing side profile, chin on hand, elbow on the desk top, headphones. Cat curled on the desk left of his arm. Clock on the desk left of the monitor. Hanging plants, string lights, shelf with books and a lantern, poster, bed corner on the right.
2. **What ends the half-body.** The board's panel edge crops him; our 480×352 canvas is taller than that panel, so something must. Default **(a)**: the room prompt puts a foreground element across the bottom of the seat (desk side or a low shelf / bed edge in front of his waist), cut as a foreground piece. Alternative **(b)**: draw the full seated body and chair seat (drops "half-body"). Open question 2.
3. **Framing.** The board panel is about 2.25:1; the canvas is 1.36:1. The extra height goes to the ceiling (shelves, string lights) and to the foreground strip from decision 2, not to a taller window.
4. **Names** (unique across A, B and C's planned `Neon*`): scene `VioletDesk01`, perspective `violet-desk-side-v1`, characters `VioletBoy`, `VioletGirl`, pets `VioletOrangeCat`, `VioletBlackCat`, scenery `VioletCityRain`, `VioletCityDusk`, clock `VioletClock`. Sources `ArtLab/type-d-violetdesk/`, log `docs/logs/art-D-violetdesk.md`.
5. **Glass key colour** `#FF00FF`, which appears nowhere else (A's lesson; B's green clashed with the monitor code).

## Review Focus

1. Character sprite carries stray room pixels (fringe, keyboard) → check with `lint_sprite` and `get_color_stats` against the key colour; test in Task 2.
2. Pose edits drift in scale or seat position → each pose overlaid on the rest pose with `compare_frames`; the seat line (lowest body row) moves by 0 px. Task 3.
3. Character or cat anchor outside the safe rectangle (B lost its shoes) → `SpritePack.problems()` is run by the iPad tests for every bundled pack. Task 2.
4. Colours of drawn parts (music skin, rain, clock) clash with the room → sampled from the room, never invented. Task 4.
5. Switching from A or B to D resets the saved character to D's first pack and keeps working → `testArtSetDRunsTheEngineUnchanged`. Task 2.
